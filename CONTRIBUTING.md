# Contributing

## Before changing a case

1. Read the existing case completely.
2. Preserve documented facts that are already supported.
3. Separate fact, attributed statement, interpretation, and inference.
4. Do not add private-life details unless they are public, reliable, and directly relevant to the decision model.
5. Add source URLs that are reachable and specific to the claim.
6. Do not inflate the case count by adding weakly sourced profiles.

## Before submitting a change

- Validate YAML and JSON syntax.
- Check internal file references.
- Check that README claims match the actual repository tree.
- Check that counterfactual scenarios are labeled as counterfactual/inference rather than historical fact.
- Prefer a small, reviewable change over a wholesale rewrite.
